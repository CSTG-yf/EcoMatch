# FE-05 自定义分析看板

## 1. 目标与边界

FE-05 在现有银行问数结果和 BE-12 看板安全接口之上交付前端闭环：

- 将一次已完成的问数结果保存为看板组件；
- 提供看板列表、编辑器和只读展示页；
- 支持布局、组件配置、全局筛选和刷新周期；
- 支持复制、发布、停用及访问范围设置；
- 所有读取和写入继续由服务端执行身份、机构、主题域和对象权限校验。

本任务不重做 BE-12 的持久化、权限、状态机、审计和乐观锁，也不提前实现
FE-06 的导出中心或受控分享。

## 3. 服务契约

FE-05 复用 `/api/semantic/dashboard`：

- `GET /api/semantic/dashboard`：按主题域、状态和分页查询看板；
- `GET /api/semantic/dashboard/{id}`：获取有权访问的看板；
- `POST /api/semantic/dashboard`：创建草稿；
- `PUT /api/semantic/dashboard/{id}`：携带 `version` 更新；
- `POST /api/semantic/dashboard/{id}/copy`：复制；
- `POST /api/semantic/dashboard/{id}/publish`：发布；
- `POST /api/semantic/dashboard/{id}/disable`：停用；
- `DELETE /api/semantic/dashboard/{id}`：删除。

状态只使用 `DRAFT / PUBLISHED / DISABLED`，访问范围只使用
`PRIVATE / ORGANIZATION / DOMAIN`。前端显示服务端返回的 owner、机构、版本和
更新时间，不伪造管理员能力。

`config` 使用 JSON 对象，首版约定：

```json
{
  "schemaVersion": "1.0",
  "layout": {
    "columns": 12,
    "rowHeight": 72
  },
  "globalFilters": [],
  "refreshIntervalSeconds": 0,
  "components": []
}
```

前端不得在 `config` 中写入物理 SQL、Token、密码或凭据。组件最多 100 个；
名称、描述、配置大小和结构限制以 BE-12 的服务端校验为最终事实源。

## 4. 界面契约

### 4.1 看板列表

- 按主题域加载本人可见看板，支持状态筛选和关键词筛选；
- 显示名称、状态、访问范围、所有者、更新时间和组件数量；
- 加载失败显示重试，不显示旧缓存为“最新数据”；
- 无数据时提供“从问数结果创建”入口。

### 4.2 看板编辑器

- 顶部展示看板名称、草稿/发布/停用状态、保存状态和访问范围；
- 左侧提供看板切换及组件目录，中央为 12 列画布，右侧为当前组件或看板配置；
- 支持组件选择、布局调整、删除、标题、图表类型和刷新周期配置；
- 全局筛选只保存语义字段、运算符和值，不保存物理 SQL；
- 更新必须携带当前 `version`。服务端报告版本冲突时保留本地未保存内容，并提供
  “重新加载最新版本”和“复制为新看板”。

### 4.3 从问数结果保存

- 仅允许保存已成功且用户当前可见的问数结果；
- 对空结果、失败结果和无权限结果禁用保存并解释原因；
- 创建前确认看板、组件标题、访问范围和刷新策略；
- 创建成功后可继续问数或进入看板编辑器。

### 4.4 发布与停用

- 发布前确认名称、至少一个有效组件及访问范围；
- 组织范围缺少可信机构属性时展示服务端错误，不允许前端绕过；
- 发布和停用都携带版本并展示明确结果；
- 危险操作使用确认对话框，失败后状态保持不变。

## 5. 验收场景

采用紧凑 BDD/TDD：

1. 给定一次成功问数，当用户保存结果时，则创建包含语义查询配置的草稿组件。
2. 给定空结果或无权限结果，当用户查看保存入口时，则入口禁用且原因可见。
3. 给定已有草稿，当用户调整布局和筛选并保存时，则请求携带当前版本。
4. 给定服务端版本冲突，当保存失败时，则本地编辑内容不丢失并提供恢复路径。
5. 给定有发布权限的草稿，当用户发布时，则状态更新为 `PUBLISHED`。
6. 给定无对象权限的用户，当列表或详情接口拒绝时，则页面显示无权限状态，
   不展示样例或上一次看板数据。
7. 给定 390px 视口，当用户编辑看板时，则画布可横向浏览，配置面板使用抽屉，
   保存和返回仍可达。
